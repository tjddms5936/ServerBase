# RF 정상 묶음 오탐 진단과 보정 사전 설계

## 이번 단계의 범위

기존 RF leaf=5·threshold=0.3을 고정하고 Train/Validation을 재예측했다. 새 모델 학습·threshold 탐색·Test CSV 접근·트래픽 송신·배포는 하지 않았다.
이미 사용한 Test는 기존 최종 JSON 보고서의 승인 보류 근거만 인용했다. 이 분석은 Test 공개 후의 개발 진단이며 미관측 데이터에 대한 독립 검증이 아니다.

## 기존 모델 재예측

| 자료 | 메시지 | FP | FN | FPR | Recall |
| --- | ---: | ---: | ---: | ---: | ---: |
| train | 1538 | 113 | 0 | 10.77% | 100.00% |
| validation | 513 | 30 | 9 | 8.60% | 94.51% |

Train 성능은 학습 자료에 대한 참고값이며 일반화 성능이 아니다. Validation은 이전 후보·threshold 선정에 이미 사용됐다.

## 입력과 관측 시점의 단서

RF의 시간 관련 중요도 합은 82.07%다. 이는 학습 트리의 불순도 감소 중요도이며 인과관계나 판단의 기여 비율을 증명하지 않는다.
- `packet_size`: 0.017807
- `payload_size`: 0.019318
- `connection_duration_ms`: 0.428110
- `message_interval_ms`: 0.392545
- `bytes_received_total`: 0.089050
- `bytes_sent_total`: 0.053171
- `error_count_total`: 0.000000

정상 묶음 FP 21건의 파싱 간격 중앙값은 0.041000ms, 최댓값은 0.134000ms다.
이 중 첫 메시지는 5건, 이전 메시지와 누적 수신량이 같은 행은 16건이다.

한 번의 RecvCompleted에서 받은 전체 바이트가 먼저 누적되고 그 뒤 각 PacketParsed가 발생한다. 따라서 뒤 프레임까지 이미 수신한 바이트가 앞 메시지 snapshot에 포함될 수 있다. 이는 실제로 이미 관측한 값이며 미래 시각을 읽는 누출과는 다르지만, 현재 프레임까지 파싱한 바이트와 의미가 다르다.

같은 수신 counter와 짧은 파싱 간격은 묶음 처리의 단서다. recv id나 클라이언트 송신 간격 자체는 관측하지 않으므로 실제 TCP 패킷 묶음 경계를 확정하지 않는다.

## 보정 후보와 새 데이터 계획

| 후보 | 입력 표현 | 입력 수 |
| --- | --- | ---: |
| rf_raw7 | 원본 7개 재학습 대조군 | 7 |
| rf_without_io5 | 누적 송수신량 제외 | 5 |
| rf_prefix_mean5 | 누적 송수신량 제외 + 과거·현재 평균 파싱 간격 | 5 |
| rf_prefix_mean_parsed6 | 평균 파싱 간격 + 현재까지 파싱한 프레임 크기 합 | 6 |

트리 수 100·leaf 5·seed 42를 유지하고 후보 4개 × threshold 0.3/0.4/0.5/0.6/0.7의 20개 조합만 새 Validation에서 비교하도록 고정했다. 아직 학습하거나 후보를 선정하지 않았다.

새 캠페인은 6개·계획 run 378개·계획 세션 1512개다. 각 캠페인에서 정상 묶음 batch 1/4/8과 pacing 3개 범위를 9조합으로 교차한다. 같은 반복의 burst는 동일 크기·개수 범위·batch·동시성을 사용하고 지정 대기만 0이다.

캠페인 역할은 새 Train 3개·Validation 1개·Test 2개다. seed와 파생 run seed가 이전 계획과 겹치지 않음을 확인했다. 이 값들은 계획이며 실제로 수집한 데이터가 아니다.

기존 전체 FPR 10%·Recall 50%·비용 한도를 유지하고 정상 묶음 FPR 10% 이하도 별도 요구한다. 새 Validation에서 후보를 잠근 뒤 새 Test로만 승인 확인한다. 기준 미달이면 미선정/승인 보류하며 Test 점수로 정책을 바꾸지 않는다.

## 한계와 다음 작업

- 학습된 중요도와 오분류의 상관은 원인 확정이나 보정 효과 검증이 아니다.
- 단일 수신의 누적 바이트와 현재 프레임의 파싱 합은 의미가 다르며 기존 v2 수집 자체가 잘못됐다고 단정하지 않는다.
- 평균 간격도 파서 처리 시각의 평균이지 클라이언트 송신 간격이나 TCP 패킷 도착 간격이 아니다.
- 첫 정상 묶음과 burst의 짧은 prefix는 같은 관측을 가질 수 있다. 과거가 없는 순간의 정보를 복원하지 못한다.
- 파생 입력은 종료 summary를 쓰지 않는다. 누락된 메시지를 0이나 미래 데이터로 채우지 않는다.
- 본문 내부 유효성·의도·실제 공격을 관측하지 않는다. error_count가 정답이나 현재 메시지의 검증 결과가 아니다.
- 새 seed·캠페인도 같은 생성기·장비의 실험이다. 실제 침입 탐지 일반화를 보장하지 않는다.
- 실시간 prefix 상태·누락 감지·수명 관리 및 새 모델 학습·비용·독립 승인은 후속 작업이다.

다음 커밋은 이 설계를 실제 수집기의 별도 실행 경로에 연결하여 새 캠페인을 수집·품질 검증하고 3/1/2 역할로 분리하는 단계다. 그 다음 새 Train 전용 학습·Validation 선정·비용 확인·새 Test 승인 순서로 진행한다.
