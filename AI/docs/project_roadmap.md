# 최종 마무리까지의 작업 로드맵

## 완료 기준

최초 목표였던 공개 데이터 연구, 직접 학습한 baseline, 한계 분석, LSTM 또는 Transformer 개선 모델, 성능·지연시간·메모리 비교, 실제 TCP 서버 추론 연동과 포트폴리오 문서까지 포함한다. 단순히 dummy 응답이 오거나 학습 모델 하나를 연결한 상태를 최종 완료로 정의하지 않는다.

현재 **운영 baseline 학습·Validation 선정, 오분류·관측 한계 분석, 독립 캠페인 6개 수집·검증·분리, 고정 기존 모델 진단과 새 Train 전용 보강 LR/RF 학습·선정·비교까지 완료**했다. 아래 2단계가 완료돼 **이제 큰 작업 묶음은 5개 남는다**. 전체를 데이터셋 구성부터 세면 8개 작업 묶음 중 3개를 마쳤다. 단계는 구현·실험 묶음 수이지 작업 일수나 실행 명령 수가 아니다. 데이터나 관측을 개선해야 하면 앞 단계로 돌아가 반복할 수 있다.

## 현재까지 완료

- C++ observer·feature 추출·bounded queue·HTTP worker와 dummy 결과 저장
- FastAPI v2 입력 검증과 Python 책임 분리
- UNSW-NB15 EDA·전처리·LR/RF 직접 학습·오분류·비교·validation 선정 실험
- 공개 데이터와 운영 feature 의미의 비호환 분석 및 운영 명세 확정
- 오류 경로 보강, 종료 snapshot 고정과 자동 테스트
- 독립 정답을 보존하는 비동기 JSONL 수집기
- 정상/통제된 이상 생성기와 21개 run 수집·품질 검증
- 운영 메시지 406건, run/session 비중복 train·validation·test 및 재현 manifest
- 운영 train 전용 scaler/LR 초기 학습과 validation 평가·실제 반복·가중치 기록(test 미사용)
- 같은 운영 train 전용 RF 초기 학습과 저장 LR/RF의 동일 validation 재예측·오분류 비교(test 미사용)
- 사전 protocol의 운영 후보 6개·threshold 7개 비교와 LR C=1·threshold=0.7 임시 baseline 선정(test 미사용)
- 선정 모델 FP 3건·FN 24건 추적, prefix·입력 표현·관측 한계 분석과 독립 캠페인 보강 설계
- v2 생성기 묶음·조각·동시성·타이밍 교차 제어와 실제 sendall·송신 시간 계측
- 독립 캠페인 6개·84개 run·336개 세션 실제 수집·검증, 메시지 3,122건과 캠페인 단위 Train/Validation/Test 3/1/2 분리
- 고정 기존 LR·threshold 0.7의 새 Validation 513건 단독 예측·시나리오/run/세션/prefix 진단, FP 92·FN 46·FPR 26.36%(재학습·Test 접근 없음)
- 보강 실험 사전 lock·새 Train 1,538건 전용 LR/RF 6개 학습·42개 조합과 동일 Validation 비교, RF leaf=5·0.3 선정(FP 30·FN 9·FPR 8.60%·Recall 94.51%, Test 미사용)

## 완료한 1단계

운영 LR/RF 직접 학습·초기 비교·제한된 Validation 선정 실험을 완료했다. 학습 전 protocol과 모든 42개 조합을 보관했고 LR C=1·threshold=0.7이 선정됐다. Validation FP=3, FN=24이며 malformed 두 시나리오 Recall은 0이다. 선정은 현재 실험 기준의 임시 baseline일 뿐 실제 배포 모델 확정이 아니다. 설명은 `docs/operational_validation_experiment.md`에 정리했다.

## 완료한 2단계

선정 모델의 오분류·본문 관측 한계를 분석한 뒤 독립 캠페인을 수집·분리하고, 고정 기존 모델 진단과 보강 Train 전용 학습·비교를 마쳤다. 학습 전에 후보·threshold·규칙을 고정했고 42개 조합 중 18개가 제약을 충족했다. RF leaf=5·threshold=0.3이 이번 개발 baseline으로 선정됐지만, 정상 묶음 FPR 16.15%와 생성기·본문 관측 한계가 남는다. 동일 LR C=1·0.7 재학습은 FN이 134건으로 늘었으므로 데이터 보강만으로 개선이 보장되지 않았다. 근거는 `docs/operational_augmentation_experiment.md`와 비교 보고서에 정리했다.

## 단계별 주의점

1. 완료한 운영 baseline은 UNSW 모델을 이름만 맞춰 가져오지 않고 현재 입력 7개로 직접 학습했다. scaler fit은 Train만, 설정·threshold 선정은 Validation만 사용했다. 이후 보강 실험에서도 Test를 후보 선택에 사용하지 않는다.
2. 현재 숫자형 입력으로 관측할 수 없는 본문 이상, 생성기 특성에 적응하는 편향, 작은 독립 run 수를 분석한다. 추가 데이터나 새 feature가 필요하면 독립 정답·새 의미 버전·재수집·분할까지 같이 설계한다. 오류 수로 정답을 만들지 않는다.
3. 임의 UNSW 행을 시간 순서로 연결하지 않는다. 이미 분리한 각 split의 동일 run/session 안에서 시계열 창을 만든다. 1개 메시지 뒤 종료되는 이상 시나리오의 padding·mask·판단 가능 시점과 coverage를 기록한다.
4. validation에서 실험과 모델 후보를 고정한 뒤 test를 최종 비교에 사용한다. 시계열 모델과 단일 메시지 모델의 판단 시점·평가 대상이 다르면 coverage를 따로 공개한다. 개선이 없다면 그 결과와 원인을 정직하게 기록한다.
5. LSTM이 아니라 RF가 최종 선택될 수도 있다. 비교 결과에 따른 선택 모델을 연결하고, 의미 버전·입력 순서·전처리·threshold를 산출물과 함께 고정한다. 실시간 경로에 필요한 상태 관리도 선택 모델 기준으로 검증한다.
6. HTTP 오류나 AI 지연이 TCP I/O를 막지 않는지 확인한다. 관리자용 전체 웹 대시보드는 필수 범위에 넣지 않으며 기존 세션별 결과 저장을 이용한 최소 조회·시연을 준비한다.
7. 통제된 애플리케이션 메시지 이상과 실제 네트워크 침입 탐지를 구분해 설명한다. 기존 공개 데이터 연구 결과와 운영 모델 결과를 한 성능 숫자로 합치지 않는다.

## 바로 다음 작업

고정 분할의 각 split 안에서 **동일 run/session 내부의 시계열 창 구성**을 먼저 구현하고 LSTM의 입력·padding·mask·라벨·판단 시점·실험 규칙을 설계한다. 새 Train에서만 전처리를 fit하고 Validation으로 비교한다. 미래 메시지, 종료 summary, 다른 세션·캠페인·split을 창에 합치지 않는다. 짧은 malformed 세션과 burst 초기 prefix의 coverage를 단일 메시지 baseline과 함께 기록한다. 새 Test 1,071건은 최종 비교까지 모델에 넣지 않는다.

고정 기존 LR의 새 Validation은 FP 92·FN 46건, 선정 보강 RF는 FP 30·FN 9건이다. RF가 malformed 16건을 잡았어도 내부 문자열 길이 필드를 입력에 추가한 것은 아니다. 프로토콜 검증과 AI 행동 탐지를 구분하며 LSTM도 없는 본문 정보나 과거 메시지를 복원할 수 없다. 보강 학습·개발 비교는 완료했지만 최종 Test·실모델 배포 성능은 아직 확인하지 않았다.

Test는 품질·분할 구성 외의 모델 예측·성능 평가·설정 선택에 최종 비교까지 사용하지 않고 기존 UNSW·운영 초기·선정 산출물은 덮어쓰지 않는다. 오분류 원인을 미리 단정하거나 오류 수로 정답을 만들지 않는다.

현재 데이터 규모만으로 최종 성능이나 일반화를 보장하지 않는다. 로드맵은 완료 조건을 명확히 한 것이며, 5번의 수정만 하면 무조건 완성된다는 일정 약속은 아니다.
