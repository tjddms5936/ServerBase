# 최종 마무리까지의 작업 로드맵

## 완료 기준

최초 목표였던 공개 데이터 연구, 직접 학습한 baseline, 한계 분석, LSTM 또는 Transformer 개선 모델, 성능·지연시간·메모리 비교, 실제 TCP 서버 추론 연동과 포트폴리오 문서까지 포함한다. 단순히 dummy 응답이 오거나 학습 모델 하나를 연결한 상태를 최종 완료로 정의하지 않는다.

현재 **운영 baseline·보강 학습·LSTM 실험에 이어 고정 모델의 최종 Test·비용 비교와 승인 판단까지 완료**했다. 다만 RF의 Test FPR 16.01%가 사전 상한 10%를 넘어서 **배포 승인은 보류**했다. 기본 남은 3개에 보정·새 독립 검증 1개를 추가해 **실제 남은 큰 작업 묶음은 4개**다. 최종 비교가 끝났다고 기준을 통과한 모델까지 확보한 것은 아니다. 단계는 구현·실험 묶음 수이지 일수나 커밋 수가 아니며 추가 검증이 실패하면 반복될 수 있다.

- v2 생성기 묶음·조각·동시성·타이밍 교차 제어와 실제 sendall·송신 시간 계측
- 독립 캠페인 6개·84개 run·336개 세션 실제 수집·검증, 메시지 3,122건과 캠페인 단위 Train/Validation/Test 3/1/2 분리
- 고정 기존 LR·threshold 0.7의 새 Validation 513건 단독 예측·시나리오/run/세션/prefix 진단, FP 92·FN 46·FPR 26.36%(재학습·Test 접근 없음)
- 보강 실험 사전 lock·새 Train 1,538건 전용 LR/RF 6개 학습·42개 조합과 동일 Validation 비교, RF leaf=5·0.3 선정(FP 30·FN 9·FPR 8.60%·Recall 94.51%, Test 미사용)
- 동일 campaign/run/session의 최대 길이 8 시계열 입력 Train/Validation 구성·원본 대조, 짧은 창·길이 1 보존, 오른쪽 padding·mask·LSTM 설계(학습·scaler fit·Test 접근 없음)
- 원본 Train 1,538행 전용 scaler·LSTM hidden 16/32 직접 학습, 최적 epoch 30/27, 14개 조합의 LSTM 후보 내 h16·0.5 선정과 동일 Validation RF 비교(학습·실험 완료, Test 미사용)
- LSTM의 정상 오탐 감소·이상 누락 증가, 길이 1·malformed·burst prefix 한계 기록과 실제 재학습 손실·가중치·checkpoint·예측 해시 재현
- 모델별 독립 프로세스의 Validation 비용 측정, RF 후보 잠금 뒤 Test 1,071건 검증·고정 예측과 holdout 사용 기록
- RF의 Test FP 122·FN 9·FPR 16.01%·Recall 97.09%, 정상 묶음 FP 103/270에 따른 승인 보류(재선정·재학습·API 배포 없음)
- 고정 RF의 Train/Validation 오탐 재예측·첫 메시지/짧은 파싱 간격/prefix 진단과 후보 4개·20개 조합·새 캠페인 6개의 보정 사전 설계(수집·학습·새 Test 승인 미실행)

## 완료한 1단계

운영 LR/RF 직접 학습·초기 비교·제한된 Validation 선정 실험을 완료했다. 학습 전 protocol과 모든 42개 조합을 보관했고 LR C=1·threshold=0.7이 선정됐다. Validation FP=3, FN=24이며 malformed 두 시나리오 Recall은 0이다. 선정은 현재 실험 기준의 임시 baseline일 뿐 실제 배포 모델 확정이 아니다. 설명은 `docs/operational_validation_experiment.md`에 정리했다.

## 완료한 2단계

선정 모델의 오분류·본문 관측 한계를 분석한 뒤 독립 캠페인을 수집·분리하고, 고정 기존 모델 진단과 보강 Train 전용 학습·비교를 마쳤다. 학습 전에 후보·threshold·규칙을 고정했고 42개 조합 중 18개가 제약을 충족했다. RF leaf=5·threshold=0.3이 이번 개발 baseline으로 선정됐지만, 정상 묶음 FPR 16.15%와 생성기·본문 관측 한계가 남는다. 동일 LR C=1·0.7 재학습은 FN이 134건으로 늘었으므로 데이터 보강만으로 개선이 보장되지 않았다. 근거는 `docs/operational_augmentation_experiment.md`와 비교 보고서에 정리했다.

## 완료한 3단계

같은 campaign/run/session의 과거·현재 창을 만들고, 원본 Train으로만 scaler를 fit해 LSTM 두 후보를 직접 학습했다. 최대 30 epoch·손실 최소 checkpoint·조기 종료·14개 정책을 사전에 고정했으며 h16·0.5가 LSTM 후보 중 선정됐다. 같은 Validation에서 RF의 FP/FN 30/9건이 LSTM에서는 13/50건이었다. 오탐은 줄었지만 누락이 늘어 Recall 우선의 전체 개선이라고 주장하지 않는다. RF를 교체하거나 추가 threshold를 사후 탐색하지 않았다. 근거는 `docs/operational_lstm_experiment.md`와 학습·재현 보고서에 있다.

## 완료한 4단계

정책·측정 방법·승인 기준을 먼저 고정하고 Validation 성능과 비용으로 RF를 잠갔다. 그 뒤 Test를 처음 예측했고 RF의 FPR 16.01%가 기준을 넘었다. 비용은 단일 요청 중앙값 4.675ms·가장 높은 프로세스 p95 6.860ms·프로세스 peak RSS 152.61MiB로 로컬 예산을 통과했으나 성능 승인에는 실패했다. Test에서 FPR이 낮은 LSTM으로 교체하거나 threshold를 바꾸지 않았다. 현재 배포 묶음은 없고 FastAPI는 dummy다. 설명·재실행 제한은 `docs/operational_final_evaluation.md`에 있다.

## 단계별 주의점

1. 완료한 운영 baseline은 UNSW 모델을 이름만 맞춰 가져오지 않고 현재 입력 7개로 직접 학습했다. scaler fit은 Train만, 설정·threshold 선정은 Validation만 사용했다. 이후 보강 실험에서도 Test를 후보 선택에 사용하지 않는다.
2. 현재 숫자형 입력으로 관측할 수 없는 본문 이상, 생성기 특성에 적응하는 편향, 작은 독립 run 수를 분석한다. 추가 데이터나 새 feature가 필요하면 독립 정답·새 의미 버전·재수집·분할까지 같이 설계한다. 오류 수로 정답을 만들지 않는다.
3. 임의 UNSW 행을 시간 순서로 연결하지 않는다. 이미 분리한 각 split의 동일 run/session 안에서 시계열 창을 만든다. 1개 메시지 뒤 종료되는 이상 시나리오의 padding·mask·판단 가능 시점과 coverage를 기록한다.
4. Validation·비용 기준으로 비교 정책·배포 후보·확인 규칙을 Test 공개 전에 고정한다. Test는 최종 비교·승인 확인에만 쓰며 최고 Test 점수로 모델이나 threshold를 사후 교체하지 않는다. 시계열 모델과 단일 메시지 모델의 판단 시점·평가 대상이 다르면 coverage를 따로 공개한다. 개선이 없다면 결과와 검증 범위를 정직하게 기록한다.
5. LSTM이 아니라 RF가 최종 선택될 수도 있다. 비교 결과에 따른 선택 모델을 연결하고, 의미 버전·입력 순서·전처리·threshold를 산출물과 함께 고정한다. 실시간 경로에 필요한 상태 관리도 선택 모델 기준으로 검증한다.
6. HTTP 오류나 AI 지연이 TCP I/O를 막지 않는지 확인한다. 관리자용 전체 웹 대시보드는 필수 범위에 넣지 않으며 기존 세션별 결과 저장을 이용한 최소 조회·시연을 준비한다.
7. 통제된 애플리케이션 메시지 이상과 실제 네트워크 침입 탐지를 구분해 설명한다. 기존 공개 데이터 연구 결과와 운영 모델 결과를 한 성능 숫자로 합치지 않는다.

## 바로 다음 작업

입력 준비 단계의 Train `(1538, 8, 7)`·Validation `(513, 8, 7)`은 모든 원본 메시지를 유지했고 당시에는 Test 창을 만들지 않았다. 이후 이번 최종 평가에서 후보 잠금 뒤 Test `(1071, 8, 7)`을 별도 경로에 만들고 원본·정답·mask·미래 혼입을 검증했다. 입력 준비와 최종 평가 데이터는 덮어쓰지 않았다.

LSTM 두 후보의 직접 학습·Validation 비교도 완료했다. 원본 Train 1,538행으로만 scaler를 fit했고 후보 둘은 30 epoch를 사용했다. h16의 최적 epoch는 30, h32는 27이며 14개 조합 중 5개가 제약을 충족했다. LSTM 후보 내 선정은 h16·0.5지만 RF보다 FN이 9→50건으로 늘었다. malformed 16건은 모두 놓쳤고 burst FN은 34건이었다. 현재 기존 RF가 더 강한 개발 비교 대상이며 실험은 `docs/operational_lstm_experiment.md`에 정리했다.

최종 비교는 완료했고 승인 보류로 마무리했다. 기존 RF는 Test Recall 97.09%지만 FPR 16.01%였고 정상 묶음 270건 중 103건을 오탐했다. 이 결과를 이유로 현재 Test에 맞춰 threshold나 모델을 다시 고르지 않는다.

정상 묶음 오탐 진단과 새 독립 평가 설계는 완료했다. 기존 Validation의 정상 묶음 FP 21건은 첫 메시지 5건과 1ms 이하 후속 16건에 집중됐고 시간 관련 불순도 감소 중요도는 82.07%였다. 이를 원인 확정으로 취급하지 않고 과거·현재 평균 파싱 간격·파싱 프레임 합 등을 비교할 입력 후보 4개와 threshold 5개, 총 20개 조합을 고정했다. 원본 v2 계약과 C++는 유지한다.

다음은 **보정 캠페인의 실제 수집·품질 검증·분할**이다. 새 캠페인 6개를 3/1/2 역할로 배정하고 정상 묶음 크기와 pacing 9조합을 교차하는 계획을 검증했다. 계획 run 378개·세션 1,512개는 아직 수집하지 않았다. 별도 실행 명령·수집 전 해시 잠금·누락/중복/정답/역할 검증을 구현해야 한다. 이후 새 Train 직접 학습·Validation 선정·비용을 거쳐 새 독립 holdout으로 확인한다. 현재 Test는 이미 사용된 진단 근거이며 새 정책의 독립 승인 점수로 재사용하지 않는다. 설명은 `docs/operational_rf_diagnosis.md`에 있다.

추가 보정 묶음은 진단·설계만 완료했고 승인까지 끝나지 않았으므로 남은 큰 묶음은 4개 그대로다. 각 묶음 안의 수집·학습·평가 커밋을 끝낼 때마다 4→3→2로 줄어드는 것은 아니다.

승인된 모델을 확보하기 전에는 dummy를 실제 배포 모델로 교체하지 않는다. 보정이 통과하면 남은 FastAPI·TCP 통합·포트폴리오 3개로 진행한다. 자동 차단과 실제 운영 승인은 현재 범위에서 보장하지 않는다.

고정 기존 LR의 새 Validation은 FP 92·FN 46건, 선정 보강 RF는 FP 30·FN 9건이다. Test의 RF는 FP 122·FN 9건이었다. malformed를 잡았어도 내부 문자열 길이 필드를 입력에 추가한 것은 아니다. 프로토콜 검증과 AI 행동 탐지를 구분하며 LSTM도 없는 본문 정보나 과거 메시지를 복원할 수 없다. 실제 API/TCP 모델 연동·장애·부하 검증은 아직 하지 않았다.

현재 Test는 잠근 고정 정책의 최종 비교에 처음 사용했으며 앞으로 새로운 미사용 Test라고 주장하지 않는다. 같은 정책 확인과 바뀐 정책의 새 독립 평가를 구분하고 기존 산출물은 덮어쓰지 않는다. 오분류 원인을 미리 단정하거나 오류 수로 정답을 만들지 않는다.

현재 데이터 규모만으로 최종 성능이나 일반화를 보장하지 않는다. 로드맵은 완료 조건을 명확히 한 것이며, 4번의 수정만 하면 무조건 완성된다는 일정 약속은 아니다.
